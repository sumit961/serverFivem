# cm-phone

Character-based phone platform for CM ROLEPLAY: phone number, contacts, SMS (direct + small groups, offline delivery),
calls (server-authoritative state), blocking, emergency requests, classifieds, intentional location sharing.
Owns phone persistence only. It integrates with owner systems and never absorbs them.

## Identity model

`characters.id` (character ID) → phone number (`AAA-BBBB`). Numbers are generated by the server, stored in
`cm_phone_numbers` with `PRIMARY KEY(character_id)` and `UNIQUE(phone_number)`, and retried on collision.
FiveM source IDs are used only to deliver live events; they are never persisted or returned to clients.
`virtual.lua` in cm-items already declares `phone` as a **virtual** item owned by `cm-phone` (not an inventory item), so
phone access is character-level: an absent inventory item never locks a player out. The SIM card item remains a cm-store
product; V1 attaches no gameplay to it.

## Controls

`F1` (rebindable under Key Bindings) or `/phone`. ESC steps back, then closes. Quick call commands while closed:
`/phoneanswer`, `/phonedecline`, `/phonehangup`.

## Data (`server/schema.lua`, additive `CREATE TABLE IF NOT EXISTS`, never reset on start)

`cm_phone_numbers`, `cm_phone_contacts`, `cm_phone_conversations`, `cm_phone_conversation_members`, `cm_phone_messages`,
`cm_phone_calls`, `cm_phone_blocks`, `cm_phone_adverts`. Character columns are `VARCHAR(50)` (utf8mb4_general_ci) to match `characters.id`.
Conversations are keyed by membership rows; a direct conversation has a unique sorted `direct_key` so concurrent first messages cannot create duplicates.

## Security

- Every callback resolves `source → cm-playerdata:GetCharacterId → phone number`; NUI values never name a sender, owner or call.
- Conversations/contacts are always read/written with the caller's character ID in the predicate; foreign IDs return `not_found`.
- A blocked sender gets `undeliverable` / `unavailable` (the callee is never notified); block state is checked on every send and dial.
- Rate limits per character (`Config.RateLimits`) and operation locks for groups and advert posting; call actions are idempotent.
- Text is length-bounded and control-stripped server-side; the NUI renders with `textContent` only.
- Location payloads are built from the server-observed ped position; the client only supplies a cosmetic label.
- Emergency forwards to the owners, which read the caller's ped on the server; cm-admin receives an audit log (no message text).
- `GetCharacterByPhoneNumber`, `SendSystemMessage`, `CreateNotification` require `GetInvokingResource()` in `Config.TrustedResources`.
- No export acts "as" a character; there is no `SendCharacterMessage`.

## Economy

Phones are economy-neutral except the classified fee, a small sink (`Config.Adverts.fee`, temporary 1,500 ≈ 2.4 minutes of baseline
City Support, per `agent-docs/CM_ECONOMY_STANDARD.md` §3). Nothing in the phone creates money. A failed advert insert refunds the exact amount to the account charged.
